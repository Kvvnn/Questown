# Questown Product Brief

## 한 줄 정의

Questown은 사용자의 현재 컨텍스트에 맞는 루틴 세션을 열고, 그 플레이 결과를 건물과 타운으로 축적하는 컨텍스트 기반 루틴 게임이다.

## 문제와 기회

기존 to-do 앱은 사용자가 직접 목록을 정리하고 우선순위를 해석해야 한다. 이 방식은 계획에는 강하지만, 실제 실행 순간에는 다음 문제가 반복된다.

- 지금 무엇을 해야 하는지 다시 판단해야 한다.
- 짧은 행동을 시작하기 위해 긴 리스트를 다시 읽게 된다.
- 실패 경험이 체크리스트 미완료로 남아 죄책감이 커진다.
- 하루의 수행 흔적이 감정적으로 남지 않는다.

Questown의 기회는 여기에 있다. 사용자가 “목록을 관리”하는 대신 “지금 할 수 있는 짧은 한 판”을 시작하게 만들면, 실행 진입 장벽을 크게 낮출 수 있다.

## 제품 비전

Questown은 생산성 도구가 아니라 생활 리듬을 플레이 가능한 형태로 바꾸는 게임형 루틴 시스템이다.

- 홈은 계획 보드가 아니라 런처다.
- 사용자는 개별 todo를 관리하는 대신 루틴 세션을 시작한다.
- 세션 결과는 floor가 되고, 하루는 building이 되고, building은 month town이 된다.
- AI는 일정 관리자보다 게임 마스터에 가깝다. 해야 할 일을 강요하기보다, 타이밍과 난이도를 조정하고 분위기를 연출한다.

## 북극성

사용자가 앱을 열었을 때 “오늘 뭘 정리해야 하지?”가 아니라 “지금 시작할 한 판이 뭐지?”라고 느껴야 한다.

정서적 목표는 다음과 같다.

- 압박보다 흐름
- 실패보다 부분 성공
- 자책보다 성장 흔적
- 체크리스트보다 플레이 감각

## 핵심 차별점

1. 컨텍스트 기반 실행  
   시간, 상황, 이후에는 위치까지 활용해 적절한 루틴을 제안한다.
2. 세션 중심 UX  
   리스트를 오래 읽지 않고, 시작 가능한 루틴을 바로 플레이하게 한다.
3. 누적되는 감성 피드백  
   세션 결과가 floor, roof, ornament, town으로 축적된다.
4. AI 게임 마스터  
   AI는 루틴 추천, 시간 조정, surprise quest, 리뷰 코멘트를 담당한다.

## 대상 사용자

### 1차 타깃

- 평일 루틴이 반복되는 직장인, 학생, 프리랜서
- “계획은 세우지만 실행 진입이 느린” 사용자
- 작은 행동을 빠르게 시작할 수 있는 모바일 경험을 선호하는 사용자

### 2차 타깃

- 습관 앱이 너무 딱딱하다고 느끼는 사용자
- 게임적인 성장 피드백을 동기 요소로 느끼는 사용자
- 아침/외출/귀가/취침 전 루틴을 안정화하고 싶은 사용자

## 핵심 사용 시나리오

### 시나리오 1: 모닝 루틴

- 사용자가 홈을 열면 `Morning Reset`이 지금 시작 가능한 루틴으로 보인다.
- 한 번 탭하면 세션 화면으로 진입한다.
- 3~5개의 짧은 step을 타이머 기반으로 수행한다.
- 세션 종료 후 등급, 점수, combo, 새 floor 생성 연출을 본다.

### 시나리오 2: 나이트 루틴

- 밤 시간대에 `Night Shutdown` 추천이 떠 있다.
- 사용자는 짧게 세션을 수행하고 하루 building의 roof를 완성한다.
- 리뷰 화면에서 오늘의 흐름과 내일 추천을 본다.

### 시나리오 3: AI 개입

- 최근 며칠간 특정 step에서 자주 지연이 발생한다.
- AI는 다음 세션에서 해당 step의 권장 시간을 완화하거나 분리된 루틴을 제안한다.
- 사용자는 AI가 강제로 바꾸는 것이 아니라 “제안”을 받고 수용한다.

## MVP 범위

이번 문서 세트 기준 MVP는 다음까지 포함한다.

- 수동 시작 루틴
- 시간 기반 추천/진입
- 루틴 세션 플레이
- step 타이머, pause, skip, complete
- 점수, combo, grace, grade
- 세션 결과 화면
- floor 생성
- 하루 리뷰와 roof 정산
- 월간 town 반영
- AI 시간 조정, AI 추천, AI 리뷰 코멘트, surprise quest 초안 생성

## 비목표

MVP에서는 아래를 하지 않는다.

- 위치 기반 trigger 실제 동작
- 백그라운드 geofence
- native shell 전환
- 고급 3D town
- 다중 프로젝트/업무 보드형 생산성 기능
- 일정 캘린더 편집기

## 성공 지표

### 행동 지표

- 홈 진입 후 세션 시작 전환율
- 하루 1회 이상 세션 완료율
- Morning / Night 루틴 주간 반복 유지율
- 세션 중 이탈률
- 리뷰 화면 도달률

### 정성 지표

- “할 일 앱 같다”보다 “짧은 게임 같다”는 피드백 비율
- 실패가 죄책감으로 남지 않는다는 반응
- building/town 축적이 계속 쓰게 만드는 요소라는 반응

### MVP 판정 지표

- 핵심 루틴 2종 이상에서 7일 연속 사용 패턴이 보이는가
- 시간 기반 추천이 수동 시작 대비 실행 전환을 올리는가
- AI 제안이 실제 수락되며 다음 세션 성과를 개선하는가

## 현재 코드베이스와의 관계

현재 저장소는 `QuestItem / DailyRecord / Today/Town/Manage` 중심의 quest/todo 앱 구조를 갖고 있다. 이는 목표 제품의 최종 구조가 아니라 전환 전 baseline이다.

- 현재: 날짜 중심 기록 + 퀘스트 체크
- 목표: 루틴 세션 중심 실행 + building/town 집계

따라서 이후 구현은 기존 구조를 유지하는 것이 아니라, routine/session 중심 모델로 옮겨 가는 migration 관점을 전제로 한다.
