# Questown UI Principles

## 제품 자세

Questown의 UI는 생산성 대시보드가 아니라 게임 런처와 플레이 화면이어야 한다.

- 홈은 정보판이 아니라 시작점이다.
- 세션은 목록 소비가 아니라 행동 실행 화면이다.
- 결과 화면은 짧고 만족스러워야 한다.
- 리뷰 화면은 하루를 평가하는 재판장이 아니라 성장 흔적을 보여주는 요약 화면이어야 한다.
- 타운은 계획 공간이 아니라 결과 감상 공간이다.

## 경험 원칙

### 1. 계획보다 실행

사용자는 앱을 열자마자 바로 시작 가능한 행동을 봐야 한다. 많은 옵션을 읽고 판단하는 구조는 피한다.

### 2. 한 번에 하나의 행동

현재 화면에서 가장 중요한 행동은 항상 하나여야 한다. 특히 홈과 세션 화면에서는 주 CTA가 시각적으로 명확해야 한다.

### 3. 짧고 빠른 루프

세션 시작, step 전환, 결과 정산, 리뷰 진입은 모두 짧고 리듬감 있게 이어져야 한다. 불필요한 중간 확인 화면은 줄인다.

### 4. 즉시 피드백, 늦은 축적

step 완료 시에는 즉각적인 피드백을 주고, 세션/하루/월간 성과는 building과 town에 누적한다.

### 5. 실패를 벌처럼 보이지 않게

오버타임, skip, partial은 부드럽게 표현한다. UI는 실망을 전달하더라도 낙인을 찍지 않는다.

### 6. 모바일 우선

세션 화면은 모바일 세로 화면 기준으로 설계한다. 스크롤보다 탭, 요약보다 행동, 작은 텍스트보다 큰 상태 표시를 우선한다.

### 7. 감정적 보상

숫자만 남기지 말고, 시각 변화와 분위기 변화를 함께 준다. floor, roof, ornament, town은 기능이 아니라 동기 설계다.

### 8. AI는 지시자가 아니라 디렉터

AI 관련 UI는 “해야 한다”가 아니라 “지금 하면 좋다”는 제안형이어야 한다. 설명 가능성과 수용 여부가 항상 보여야 한다.

## 정보 위계

### 홈 / 런처

홈의 역할은 “지금 시작 가능한 루틴을 보여주고 바로 진입시키는 것”이다.

홈에서 우선순위는 다음 순서를 따른다.

1. 지금 시작 가능한 루틴 1개
2. 다음 예정 루틴 1개
3. 오늘 building 진행 요약
4. streak / combo 요약
5. surprise quest 1개

홈에서는 아래 패턴을 금지한다.

- 긴 리스트
- 다중 섹션 보드
- 세부 설정 패널 상시 노출
- 관리자용 지표가 주 콘텐츠가 되는 구조

### 루틴 세션 화면

세션 화면은 풀스크린에 가까운 몰입형 구조로 설계한다.

가장 크게 보여야 하는 정보:

- 현재 step 이름
- 남은 시간
- 현재 step 진행 상태
- 전체 세션 진행률
- 주 행동 버튼

보조 정보:

- 다음 step 미리보기
- 현재 combo
- pause / skip
- 작은 building 또는 캐릭터 반응

세션 화면은 한 화면 안에서 거의 모든 조작이 끝나야 한다. 스크롤은 최소화한다.

### 세션 결과 화면

결과 화면은 짧고 강하게 끝나야 한다. 체류 시간 목표는 2~4초다.

반드시 보여줄 것:

- 결과 등급
- 총점
- combo / bonus 요약
- 새 floor 생성 연출
- 획득 ornament 여부
- 짧은 AI 코멘트

결과 화면은 상세 분석보다 “잘 끝냈다”는 감각을 우선한다.

### 하루 리뷰 화면

하루 리뷰는 하루의 building을 크게 보여주는 정산 화면이다.

반드시 보여줄 것:

- 완성된 building
- roof 타입
- 오늘 수행한 루틴 목록
- streak 변화
- surprise quest 결과
- AI 하루 요약
- 내일 추천 루틴

리뷰 화면의 목적은 반성문이 아니라 정리와 다음 진입 준비다.

### 타운 화면

타운은 결과와 누적 감상을 위한 공간이다.

- 홈보다 먼저 보여서는 안 된다.
- 세션 시작 CTA와 경쟁하면 안 된다.
- 월간 리듬과 성장 흔적을 한눈에 보는 역할을 한다.
- 세부 데이터는 오버레이나 보조 레이어로 열어야 하며, 기본 레이아웃은 감상 중심이어야 한다.

## 상호작용 원칙

### 시작 원칙

- 홈에서 루틴 시작은 1탭 또는 최대 2탭 안에 가능해야 한다.
- 홈에 진입했을 때 주 CTA는 “지금 시작”이어야 한다.
- 추천 이유가 있다면 짧게 붙이되, CTA보다 크면 안 된다.

### 세션 조작 원칙

- `완료`, `pause`, `skip`의 의미는 명확해야 한다.
- `완료`는 항상 가장 큰 버튼이다.
- `pause`는 존재하지만 주 행동이 되어서는 안 된다.
- `skip`은 숨기지 않지만 실수로 누르기 어렵게 배치한다.

### 전환 원칙

- step 전환은 200~500ms 수준의 짧은 반응형 전환을 사용한다.
- 결과 화면은 빠르게 진입하고, 사용자가 원하면 즉시 닫을 수 있어야 한다.
- 리뷰 화면은 하루의 감정적 클로징을 주되, 과하게 길면 안 된다.

### 알림 / 위젯 진입 원칙

- 알림은 할 일 목록이 아니라 “지금 열 수 있는 세션”을 알려야 한다.
- 알림 카피는 제안형이어야 한다.
- 위젯이나 알림에서 진입했을 때도 첫 화면은 홈이 아니라 해당 세션 바로 전 단계 또는 세션 화면이어야 한다.

## 감정 설계

### 카피 톤

- 명령형보다 제안형
- 평가형보다 관찰형
- 벌점형보다 회복형

좋은 예시:

- “지금 Morning Reset을 시작하면 흐름을 잡기 좋아요.”
- “오늘은 Partial이지만 리듬은 이어졌어요.”
- “이 step은 시간을 조금 더 길게 잡는 편이 맞아 보여요.”

피해야 할 예시:

- “아직 이것도 안 했어요.”
- “실패했습니다.”
- “오늘 생산성이 낮습니다.”

### 시각 반응

- 성공은 밝고 가볍게 축하한다.
- partial은 부드러운 중립 톤으로 처리한다.
- 실패성 이벤트라도 파괴적 연출은 피한다.
- streak와 ornament는 수집의 즐거움으로 느껴지게 해야 한다.

## 실패 보호 원칙

- 시간 초과는 즉시 실패가 아니다.
- 한 세션 내에 grace를 허용한다.
- partial도 리뷰와 성장 서사 안에 포함한다.
- 최근 성공률이 낮아지면 AI는 난이도를 낮추거나 루틴을 분리 제안해야 한다.
- 연속 저성과 시에도 홈의 분위기는 압박보다 회복 쪽으로 이동해야 한다.

## 금지 패턴

다음 패턴은 Questown의 정체성을 훼손하므로 금지한다.

- 리스트 중심 홈
- 생산성 앱 같은 체크박스 보드가 메인인 구조
- 세션 시작보다 설정 편집이 먼저 보이는 구조
- 긴 폼 입력을 시작 조건으로 요구하는 구조
- 실패를 빨간 에러처럼 노출하는 패턴
- AI가 사용자 동의 없이 루틴을 강제 수정하는 패턴
- 타운이 홈보다 더 중요한 내비게이션 목적지가 되는 구조
- 성과 숫자만 크고 감정적 보상이 없는 결과 화면

## 현재 코드베이스에 대한 적용 메모

현재 저장소의 `Today / Town / Manage`와 quest 리스트 구조는 목표 제품의 최종 UX가 아니다.

- `Today`는 장기적으로 `홈/런처 + 루틴 진입`으로 재구성되어야 한다.
- 현재 quest list는 migration 중 임시 입력 수단으로만 남길 수 있다.
- `Town`은 결과 확인 공간으로 유지하되, 세션 시작 흐름을 방해해서는 안 된다.
